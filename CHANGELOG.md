## [Unreleased]

### Added

- Stage 5d service wiring and entry point (`reframe.api.service`, `reframe.cli`): create_service composition root — one FastAPI app carrying /chat, /health, /instruments, and /checkins with deterministic safety routing unchanged; tracker selection by injection factory, SQLite path, or in-memory dev default; the SQLite store is attached to app.state and closed on shutdown. Runnable via `python -m reframe.cli` (--host/--port/--db/--log-level, port-range validation): development without an API key still serves — scripted crisis/review routes keep working while generated turns return a clean 503 via the unconfigured generator (fail-closed per reframe.config); production without a key refuses to start. 16 new tests (631 total), 100% statement and branch coverage. Also corrected store.py's lifecycle docstring to match the shutdown-close behavior.
- Stage 5c durable persistence (`reframe.measurement.store`, `reframe.measurement.persistent`): CheckInStore protocol + SqliteCheckInStore (stdlib sqlite3, single lock-guarded connection, insert-ordered rows). Fail-closed loading — a malformed stored row (bad JSON, non-int responses, unknown flag value, bad date, empty instrument id) raises naming the row id instead of being skipped; flags restore verbatim with no re-scoring. PersistentCheckInTracker extends the in-memory tracker with a threading lock (FastAPI sync routes run in a threadpool), persists only accepted check-ins (unknown/out-of-order rejections never reach the store), and rolls back the in-memory append when persistence fails so memory and disk can never diverge. 30 new tests (615 total), 100% statement and branch coverage.
- Stage 5b measurement endpoints (`reframe.api.measure`): GET /instruments serves full form-ready specs (items, answer options, band-partitioned severities, citations) for PHQ-9/GAD-7/K-10; POST /checkins records a dated check-in and returns scoring plus computed flags and escalation routing (item 9 -> hard_bypass with the scripted crisis text, persistent >=16 / early-worsening -> human_review with the concern copy); GET /checkins/{id} returns per-instrument history with routing recomputed per entry. Unknown instruments -> 404; malformed bodies, impossible dates, out-of-range/out-of-order check-ins -> generic 422 with no internals. 17 new tests (585 total), 100% statement and branch coverage.
- Stage 5a API core (`reframe.api`): FastAPI app factory with dependency-injected pipeline — GET /health (version report), POST /chat mapping PipelineOutcome to pydantic wire models. Fail-closed HTTP error mapping: GenerationError -> generic 503, ValueError -> generic 422, unexpected exceptions -> generic 500, none leaking internal text (secret-token probes asserted). ChatRequest forbids unknown keys, enforces 1..4000 chars. Safety semantics verified through the HTTP layer (crisis bypass returns scripted reply + resources with the generator never called). App metadata wellness-lane linted. 23 new tests (565 total), 100% statement and branch coverage.
- Stage 4b tracking and safety wiring (`reframe.measurement`): in-memory longitudinal check-in tracker with per-instrument baselines, out-of-order rejection, and dict round-tripping for the future API layer. Pure flag computation: PHQ-9 item 9 is a single-item escalation flag (first check-in included); early-worsening adverse-event signal vs baseline within 14 days (provisional thresholds, documented as design defaults pending pilot validation, per NICE NG222 rec. 1.2.10); persistent PHQ-9 >= 16 over two consecutive check-ins triggers a referral prompt (rec. 1.4.3 applied). Routing bridges check-in flags onto the pipeline's escalation vocabulary — ESCALATE reuses the crisis_response_v1 scripted path. Summed scores never drive risk categories (NICE NG225). 56 new tests (542 total), 100% statement and branch coverage.
- Stage 4a measurement (`reframe.measurement`): verbatim PHQ-9, GAD-7, and K-10 instrument definitions (free, no-permission instruments per the research) with fail-closed scoring — item count, type (bools rejected), and range validation before any arithmetic, severity bands validated as exact partitions of each total range. SCS-SF held in a pending-verification registry, unreachable by callers until its item wording is verified against the published source. 86 new tests (486 total), 100% statement and branch coverage.
- Stage 2c output filter and pipeline orchestration (`reframe.pipeline`): Layer-5 deterministic filter blocking diagnosis claims, treatment advice, professional impersonation, risk scoring, and sycophancy in model output — plus safety-classifier reuse so crisis-level model output is always blocked. Scripted response catalog (crisis, boundary, filter fallback) with wellness-clean copy. ConversationPipeline enforces the full route matrix: crisis → hard bypass without calling the model, trauma/diagnosis/psychosis → human review without the model, normal → retrieve → generate → filter, blocked output → scripted fallback. 400 tests, 100% statement and branch coverage.
- Stage 2b constrained generation (`reframe.generation`): nine explicit system-prompt red lines (no diagnosis, treatment, impersonation, risk scoring, outcome promises; curated-exercises-only; decline-and-refer behavior), RAG-style context injection from the content library, a provider-agnostic LLM client protocol, and an OpenAI-compatible adapter (httpx, injectable transport, timeouts, sanitized errors that never contain the API key). 342 tests, 100% statement and branch coverage.
- Stage 2a content library (`reframe.content`): 12 curated exercise modules across rumination, behavioral activation, self-compassion, and emotion regulation — evidence-tiered A/B/C with real citations, contraindications, and the NICE NG222 rec. 1.2.10 early-worsening notice on every module. Deterministic rule-matched retrieval (no embeddings, no model calls) with tier-A-first selection. A wellness-lane lint test scans every content string against banned treatment/diagnosis claim patterns (fail-closed). 280 tests, 100% statement and branch coverage.
- Stage 1 safety layer (`reframe.safety`): deterministic, rule-based input classifier (23 compiled-regex rules across crisis, psychosis/mania, trauma-processing, and diagnosis-seeking signals), a fixed escalation policy table (HIGH_RISK → hard bypass with scripted crisis resources; REVIEW → human review queue; NORMAL → proceed), real crisis-resource references, and a pre-specified crisis-query audit harness (target recall 1.0, enforced by tests over a 46-case corpus). Fail-closed by design: over-flagging is the accepted direction of error; the generative model never participates in escalation decisions. 136 tests, 100% statement and branch coverage.
- Stage 0 scaffold: `src/reframe` Python package with an immutable, environment-driven settings loader (fail-closed secret boundary — production refuses to start without its API key, and secrets are excluded from all string renderings).
- TDD test suite: 21 tests written before implementation (RED → GREEN → refactor), 100% statement and branch coverage.
- CI pipeline: lint (ruff), format check, strict type check (mypy), tests on Python 3.12 and 3.14, and a gitleaks secret scan.
- Initial product repository: README, contributing guide, code of conduct, security policy, support policy, Apache-2.0 license, documentation index, and GitHub community-health templates.
- Repository standards: conventional commits, test-driven development with an 80%+ coverage gate, and a pull-request checklist requiring a pre-commit secret scan.

No implementation code has been committed. There are no releases.
